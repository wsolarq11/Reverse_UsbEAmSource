# 还原策略：L0 → L1 → L2 分层推进

> 本文是「如何把总进度推到 100%」的唯一策略真相源。所有批次、验收、口径、标记都从这里派生；冲突时以本文为准。
> 终点口径写死：**4,754 蓝图函数全部 `[S]` 忠实还原**。分层是路径，不是降低终点。

## 1. 一句话

终点是全部 `[S]`（逐寄存器忠实还原），但过程分三层推进，每层有独立验证锚，绝不一步跳终点。当前 253 批次的痛（55+ 错误、三度口径失真、批批返工）源于「每一步都直接跳 L2，中间没有验证锚」。

## 2. 三层模型（规则写死）

| 层 | 标记 | 目标 | 验证锚 | 出错时 |
|---|---|---|---|---|
| L0 | `[P]` / `[S-sig]` | 能编译、签名对 | `go build` | 编译不过，自动暴露 |
| L1 | `[S-eq]` | 行为等价 | 对拍测试 | 测试不过，自动暴露 |
| L2 | `[S]` / `[S-inline]` | 忠实还原 | 对拍 + 汇编逐条对应 | 对拍兜底抓读错 |

- L1 = 读汇编理解**意图** → 写行为等价代码 → 对拍通过。**不逐寄存器忠实**。
- L2 = 逐寄存器对应汇编。**只做核心函数**。

## 3. 覆盖策略（二八律，写死）

- **80% 长尾**（getter / 转发 / 平台适配 / 琐碎叶子）→ 终点停在 **L1**，不升 L2。
- **20% 核心**（复杂业务 / 关键算法 / 安全机制）→ 必须升 **L2**。
- 判据：一个函数若「行为等价」和「忠实还原」在可观察行为上无区别，它就是长尾，停在 L1。

## 4. 标记口径（`tools/count_funcs.sh` 是唯一真相源）

```bash
bash tools/count_funcs.sh
```

- **忠实度 FAITHFUL** = `S + S-inline` ← **总进度 100% 的唯一定义**（终点）
- **可用度 USABLE** = `S + S-inline + S-eq` ← 行为等价 100% 的过程量
- **真函数 TRUE** = `S + S-inline + S-sig` ← 排除 [P] 存根后的已落地量
- 写标记用独立子串：`// [S]`、`// [S-eq]`、`// [S-sig]`、`// [P]`。
- 禁止手抄数字改一改；每批收尾必须重跑脚本取活体值。

**识别逻辑只有一个来源**：任何其它脚本（`list_p.sh`、`p_funcs.py`、未来的分析工具）需要判定档位时，
必须与 `count_funcs.sh` 的 last 状态机逐条一致。历史教训：曾存在 4 份各自实现的判定逻辑，
其中两份漏识别 `[S-eq]` 与 `\t` 变体，对同一份代码给出矛盾档位（2026-12-12 收敛）。

## 5. 铁律（写死，新会话开工前必读）

1. 终点 = 全部 `[S]`。分层是路径，不是降低终点。
2. 签名未定型拒绝落体，宁留 `[S-sig]`/`[P]` 并写明阻断原因，不制造伪 `[S]`。
3. **L1 落体必须带对拍测试，无测试不算 L1**，只能算 `[S-sig]`。
4. L2 替换时，该函数 L1 的对拍测试必须仍通过（编译 + 对拍双保险）。
5. 口径只信 `count_funcs.sh`，历史文档数字若冲突以活体实测为准。

## 6. 对拍 harness（tools/parity/）

验证「行为等价」的唯一手段，分两级，按函数可测性降级：

- **函数级**：从原 exe 抽取函数字节码与其只读跳转表，由**独立的参考实现**（其表数据由抽取产物
  机械推导）生成黄金期望值，与重建代码对拍。
- **程序级**：跑原二进制 vs 重建二进制，比输出文件 / 配置 / 二维码 / 截图等黄金用例。
- 带 goroutine / 系统调用 / 逃逸的函数，函数级对拍不可行时降级到程序级。

### 6.1 期望值纪律（写死）

1. 期望值禁止从被测实现反推。
2. 参考实现中的**表数据**（跳转表 / 常量表）必须由抽取产物机械推导，禁止手写。
3. 对拍通过后须做**变异测试**抽样自检：注入已知变异，确认能抓到。抓不到需判定是
   "漏检"还是"该改写不可达"，后者记入验收文档。

### 6.2 已知局限

抽取器只支持**无 call 的叶子函数**；含 call 的函数门禁直接失败，不静默降级。
