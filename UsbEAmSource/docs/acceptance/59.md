## G3 逻辑等价

关键实证（asm VA → Go）：

- `launcherConfigStore.matchesPath@0x140898ca0`（0x6f, 111B）：
  `test rax,rax` 判 nil（返 false）→ `launcherConfigStorePathKey(s.path)` → `launcherConfigStorePathKey(path)`
  → 先比长度（`cmp rcx,rbx`）不等返 false，相等走 `runtime.memequal`。等价
  `launcherConfigStorePathKey(s.path) == launcherConfigStorePathKey(path)`。
- `configStoreSnapshot@0x1407a1240`（544B）：
  - 0x1407a12a0 `test rax,rax` → bs==nil 时 duffzero 160B 返空 WorkspaceLayout（rax=0）。
  - 0x1407a12bc `lock cmpxchg [rcx+0x540]` → `bs.lock`（+ lockSlow 兜底）。
  - 0x1407a12df–0x1407a130d open-coded defer Unlock（deferwrap1 = 0x1407a1460）。
  - 0x1407a132a `duffcopy+0x2f4`（160B = WorkspaceLayout）快照 `bs.workspace` → 局部区 [rsp+0x28]。
  - 0x1407a1333 `store = bs.configStore`（[rcx+0xa0]）。
  - 0x1407a1344 `store.matchesPath(workspace.ConfigFile@+0x10)`，未命中 → `launcherConfigStoreForPath`
    重建 + 回写 `bs.configStore`（含 gcWriteBarrier2 写屏障路径）。
  - 0x1407a13ca `duffcopy+0x2f4` 快照工作区 → 调用者返回槽；rax = store。

**签名实证修正（本批核心发现）**：旧骨架误写
`(*launcherConfigStore, LauncherConfig, DesktopWidgetDocument)`。真 ABI 为
`(*launcherConfigStore, WorkspaceLayout)`——第二栈返回值仅 160B（`duffzero+0x134` 与
`duffcopy+0x2f4` 均为 160B），即工作区布局快照，不含 LauncherConfig（2576B=0x142 qword）
与 DesktopWidgetDocument（2352B=0x126 qword）。调用方另以 `store.Read()` /
`store.ReadSelfContained()` 取得 cfg/widgets。
