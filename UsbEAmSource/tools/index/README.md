# tools/index —— 分析索引（SQL 查询层）

## 1. 目的

把「符号 / 蓝图 / 落地状态 / 反汇编资产 / 调用边」落进一个只读 SQLite，
让缺口分析与证据检索从「正则扫全量文本」变成「SQL join」。

## 3. 口径（硬约束）

1. **标记口径**：`common.scan_markers()` 镜像 `tools/count_funcs.sh` 的 awk 状态机，
   后者是唯一真相源（`docs/STRATEGY.md` §4）。建库后必须逐字段一致：

   ```bash
   bash tools/count_funcs.sh
   python tools/index/build_index.py --quiet
   ```

   两行输出格式相同（`FUNCS= MARKED= … TRUE=`），可直接 diff。

2. **函数名规范化**：`common.func_key()` 是全仓库唯一实现，键为点号形态、大小写敏感
   （`(*T)M` / `(*T).M` / `main.T.M` → `T.M`；`main.F` → `F`）。

3. **形态还原**：蓝图 `source_funcs.txt` 原文自身不统一，既有 `(*T)M`，也有
   `volumeIndexReadViewfindNodeIndexByFRN` 这种类型名与方法名粘连的写法。
   `common.resolve_func_key()` 用符号表（编译级产物，形态规范）把粘连名还原成点号名。
   不做这层还原，同一个函数在蓝图侧与源码侧会是两个键，缺口凭空多出假阳性。

4. **缺失判定**：`common.classify_missing()` 是唯一实现，只做**精确键相等**，
   不做短名回退。分母是蓝图（排除 `<autogenerated>`，它是 58 个函数项而非文件），
   已实现集是 `backend/*.go`（非 `_test`）的函数定义。结果分三类：

   - `MISSING` 需人工还原（当前 332）
   - `GEN` 编译器生成物（闭包 `funcN` / defer 包装 `deferwrapN` / `gowrapN` 等，当前 1169）——只是分类，不是豁免，其中有明确要落地的条目（例：`validateLauncherConfigIconData.func1`）
   - `NEVER` 永不落地名单（combridge IUnknown 自动提升、名字错配的 `screenshotLinearFloatToSRGBByte`，当前 1）——依据 `HANDOFF.md` 给新会话的三条铁律

5. **「已实现」不等于「已忠实还原」**：前者看函数定义是否存在，后者看标记
   （`S` / `S-inline`）。两者不要混用同一个数字。

## 4. 用法

```bash
python tools/index/build_index.py              # 建库（可重复，全量重写）
python tools/index/build_index.py --quiet      # 只打印计数行（diff 用）

python tools/index/q.py stats                  # 规模与标记分布
python tools/index/q.py missing --top 40       # 未落地清单（唯一数字源）
python tools/index/q.py gap --top 30           # 按文件的待还原分布（有资产优先）
python tools/index/q.py landed S-sig           # 按档位列函数
python tools/index/q.py func RunNow            # 单函数证据包（符号/蓝图/落地/资产）
python tools/index/q.py sql "SELECT ..."       # 只读逃生舱

node tools/list_missing.js --top 40            # 与上面 missing 逐字节相同（薄封装）

python tools/index/asmtool.py disasm RunNow --print
python tools/index/asmtool.py callers parseMemoryReleaseMode
python tools/index/asmtool.py scan "main.screenshot" --limit 200

python tools/go-introspect/va_dump.py <exe> 0xBASEVA LENGTH <outPrefix>   # 落盘 .bin + .asm.txt
```

`asmtool.py disasm` 的字节来源与 `tools/go-introspect/va_dump.py` 一致；
用同一函数比对时，指令序列应逐行相同（例：`main.memoryReleaseService.RunNow`
= 0x1408d3b40，138 条指令，与 `work/disasm/runnow/RunNow.asm.txt` 一致）。
符号批注两侧同走 `common.annotate_symbol`（窗口 0x2000），标注串也应逐字相同。

## 5. 已知边界

- 函数长度优先取 `va_map_fixed2.txt` 的实测值；缺失时用「下一个符号 VA − 本 VA」
  作上界，对中间夹数据符号的函数可能截短或越界，需显式 `--len` 覆盖。
- 资产命中用「资产名小写 == 函数短名小写」精确相等（当前 332 个待还原里命中 61）。
  命名带变体的资产不计入，故该数偏保守。
- 蓝图有、符号表无的条目（例如只在源码里出现、编译时被内联的函数）无法做形态还原，
  键保持蓝图原形态。当前这类为 0，仍需在新批次后复检。
- PE 读取（`va_to_off`）、符号表加载（`load_symbols`）、符号批注（`annotate_symbol`）
  的唯一实现在 `common.py`。`tools/go-introspect/` 的入口一律 import 它，不再各写一份；
  曾散在 12 个脚本里，导致同一地址在不同脚本里可能标成不同字符串。
